    Ejercicios de Git y GitHub

    A continuación tienes una colección de ejercicios prácticos para afianzar el manejo de Git y de GitHub. Los ejercicios están pensados para realizarse de forma secuencial: en los primeros trabajarás con un repositorio local llamado libro que simula la redacción de un libro, y en los últimos publicarás ese repositorio en GitHub.

    Rama principal

    Estos ejercicios utilizan master como nombre de la rama principal. Si tu versión de Git crea la rama main por defecto, sustituye master por main en todos los comandos.

    Repositorios en GitHub

    Para los ejercicios 20 a 23 es necesario disponer de una cuenta de GitHub y crear en ella los repositorios correspondientes.

    1. Configurar Git

    Configurar Git definiendo el nombre del usuario, el correo electrónico y activar el coloreado de la salida. Mostrar la configuración final.

    git config --global user.name "Tu Nombre"
git config --global user.email "tu.correo@ejemplo.com"
git config --global color.ui true
git config --list

    2. Crear un repositorio

    Crear un repositorio nuevo con el nombre libro y mostrar su contenido.

    mkdir libro
cd libro
git init
ls -la

    El comando ls -la muestra, entre otras cosas, la carpeta oculta .git que indica que el directorio ya es un repositorio Git.

    3. Crear y preparar el fichero índice.txt

    Comprueba el estado del repositorio. Crea un nuevo fichero indice.txt con el siguiente contenido:

    Capítulo 1: Introducción a Git
Capítulo 2: Flujo de trabajo básico
Capítulo 3: Repositorios remotos

    Comprueba el nuevo estado del repositorio y añade el fichero a la zona de intercambio temporal. Comprueba otra vez el estado del repositorio.

    git status

cat > indice.txt << 'EOF'
Capítulo 1: Introducción a Git
Capítulo 2: Flujo de trabajo básico
Capítulo 3: Repositorios remotos
EOF

git status
git add indice.txt
git status

    4. Realizar el primer commit

    Realizar un commit de los últimos cambios con el mensaje "Añadido índice del libro." y ver el estado del repositorio.

    git commit -m "Añadido índice del libro."
git status

    5. Modificar el índice y hacer commit

    Cambiar el fichero indice.txt para que contenga lo siguiente:

    Capítulo 1: Introducción a Git
Capítulo 2: Flujo de trabajo básico
Capítulo 3: Gestión de ramas
Capítulo 4: Repositorios remotos

    Mostrar los cambios con respecto a la última versión guardada en el repositorio. Hacer un commit de los cambios con el mensaje "Añadido capítulo 3 sobre gestión de ramas".

    cat > indice.txt << 'EOF'
Capítulo 1: Introducción a Git
Capítulo 2: Flujo de trabajo básico
Capítulo 3: Gestión de ramas
Capítulo 4: Repositorios remotos
EOF

git diff
git add indice.txt
git commit -m "Añadido capítulo 3 sobre gestión de ramas"

    6. Modificar el mensaje del último commit

    Mostrar los cambios de la última versión del repositorio con respecto a la anterior. Cambiar el mensaje del último commit por "Añadido capítulo 3 sobre gestión de ramas al índice." Volver a mostrar los últimos cambios del repositorio.

    git show HEAD
git commit --amend -m "Añadido capítulo 3 sobre gestión de ramas al índice."
git show HEAD

    El comando git show HEAD muestra el último commit y sus cambios, y git commit --amend permite reescribir su mensaje.

    7. Crear la carpeta capítulos

    Mostrar el historial de cambios del repositorio. Crear la carpeta capítulos y, dentro de ella, el fichero capitulo1.txt con el siguiente texto:

    Git es un sistema de control de versiones ideado por Linus Torvalds.

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit de los cambios con el mensaje "Añadido capítulo 1." Volver a mostrar el historial de cambios del repositorio.

    git log --oneline

mkdir capítulos
cat > capítulos/capitulo1.txt << 'EOF'
Git es un sistema de control de versiones ideado por Linus Torvalds.
EOF

git add .
git commit -m "Añadido capítulo 1."
git log --oneline

    8. Crear el capítulo 2

    Crear el fichero capitulo2.txt en la carpeta capítulos con el siguiente texto:

    El flujo de trabajo básico con Git consiste en:
1- Hacer cambios en el repositorio.
2- Añadir los cambios a la zona de intercambio temporal.
3- Hacer un commit de los cambios.

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit de los cambios con el mensaje "Añadido capítulo 2." Mostrar las diferencias entre la última versión y dos versiones anteriores.

    cat > capítulos/capitulo2.txt << 'EOF'
El flujo de trabajo básico con Git consiste en:
1- Hacer cambios en el repositorio.
2- Añadir los cambios a la zona de intercambio temporal.
3- Hacer un commit de los cambios.
EOF

git add .
git commit -m "Añadido capítulo 2."
git diff HEAD~2 HEAD

    El comando git diff HEAD~2 HEAD muestra los cambios introducidos en los dos últimos commits.

    9. Crear el capítulo 3

    Crear el fichero capitulo3.txt en la carpeta capítulos con el siguiente texto:

    Git permite la creación de ramas lo que permite tener distintas versiones del mismo proyecto y trabajar de manera simultánea en ellas.

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit de los cambios con el mensaje "Añadido capítulo 3." Mostrar las diferencias entre la primera y la última versión del repositorio.

    cat > capítulos/capitulo3.txt << 'EOF'
Git permite la creación de ramas lo que permite tener distintas versiones del mismo proyecto y trabajar de manera simultánea en ellas.
EOF

git add .
git commit -m "Añadido capítulo 3."

git log --oneline
git diff <hash-del-primer-commit> HEAD

    Para comparar la primera versión con la última, primero se localiza el hash del primer commit con git log --oneline y, a continuación, se ejecuta git diff indicando ese hash y HEAD.

    10. Añadir el capítulo 5 al índice

    Añadir al final del fichero indice.txt la siguiente línea:

    Capítulo 5: Conceptos avanzados

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit de los cambios con el mensaje "Añadido capítulo 5 al índice." Mostrar quién ha hecho cambios sobre el fichero indice.txt.

    echo "Capítulo 5: Conceptos avanzados" >> indice.txt

git add indice.txt
git commit -m "Añadido capítulo 5 al índice."

git log --oneline -- indice.txt

    El comando git log -- indice.txt muestra el historial de commits que han afectado al fichero. Alternativamente, git blame indice.txt muestra línea a línea el autor de cada cambio.

    11. Deshacer cambios en el directorio de trabajo

    Eliminar la última línea del fichero indice.txt y guardarlo. Comprobar el estado del repositorio. Deshacer los cambios realizados en el fichero indice.txt para volver a la versión anterior del fichero. Volver a comprobar el estado del repositorio.

    # Editar indice.txt eliminando la última línea
git status
git checkout -- indice.txt
git status

    git checkout -- indice.txt descarta los cambios del fichero y lo devuelve a la última versión confirmada.

    12. Quitar cambios de la zona de intercambio temporal

    Eliminar la última línea del fichero indice.txt y guardarlo. Añadir los cambios a la zona de intercambio temporal. Comprobar de nuevo el estado del repositorio. Quitar los cambios de la zona de intercambio temporal, pero mantenerlos en el directorio de trabajo. Comprobar de nuevo el estado del repositorio. Deshacer los cambios realizados en el fichero indice.txt para volver a la versión anterior del fichero. Volver a comprobar el estado del repositorio.

    # Editar indice.txt eliminando la última línea
git add indice.txt
git status
git reset indice.txt
git status
git checkout -- indice.txt
git status

    git reset indice.txt quita el fichero de la zona de intercambio temporal (los cambios vuelven al directorio de trabajo), mientras que git checkout -- indice.txt los descarta por completo.

    13. Deshacer varios tipos de cambios

    Eliminar la última línea del fichero indice.txt y guardarlo. Eliminar el fichero capítulos/capitulo3.txt. Añadir un fichero nuevo capítulos/capitulo4.txt vacío. Añadir los cambios a la zona de intercambio temporal. Comprobar de nuevo el estado del repositorio. Quitar los cambios de la zona de intercambio temporal, pero mantenerlos en el directorio de trabajo. Comprobar de nuevo el estado del repositorio. Deshacer los cambios realizados para volver a la versión del repositorio. Volver a comprobar el estado del repositorio.

    # 1. Editar indice.txt eliminando la última línea
# 2. Eliminar capitulo3.txt y crear capitulo4.txt vacío
rm capítulos/capitulo3.txt
touch capítulos/capitulo4.txt

git add .
git status
git reset
git status

# Deshacer los cambios de los archivos con seguimiento
git checkout -- .
# Eliminar el archivo nuevo que no tiene seguimiento
rm capítulos/capitulo4.txt

git status

    git checkout -- . descarta los cambios de los archivos con seguimiento (restaura indice.txt y capitulo3.txt), pero no elimina los archivos nuevos sin seguimiento como capitulo4.txt, que hay que borrar manualmente.

    14. Deshacer commits

    Eliminar la última línea del fichero indice.txt y guardarlo. Eliminar el fichero capítulos/capitulo3.txt. Añadir los cambios a la zona de intercambio temporal y hacer un commit con el mensaje "Borrado accidental." Comprobar el historial del repositorio. Deshacer el último commit pero mantener los cambios anteriores en el directorio de trabajo y la zona de intercambio temporal. Comprobar el historial y el estado del repositorio. Volver a hacer el commit con el mismo mensaje de antes. Deshacer el último commit y los cambios anteriores del directorio de trabajo volviendo a la versión anterior del repositorio. Comprobar de nuevo el historial y el estado del repositorio.

    # 1. Editar indice.txt eliminando la última línea
# 2. Eliminar capitulo3.txt
rm capítulos/capitulo3.txt

git add .
git commit -m "Borrado accidental."
git log --oneline

git reset --soft HEAD~1
git log --oneline
git status

git commit -m "Borrado accidental."

git reset --hard HEAD~1
git log --oneline
git status

    git reset --soft deshace el commit conservando los cambios en la zona de intercambio temporal, mientras que git reset --hard deshace el commit y descarta los cambios por completo.

    15. Crear la rama bibliografía

    Crear una nueva rama bibliografía y mostrar las ramas del repositorio.

    git branch bibliografía
git branch

    La rama actual aparece marcada con un asterisco. Al crearla con git branch (sin switch) seguimos en la rama master.

    16. Crear el capítulo 4

    Crear el fichero capítulos/capitulo4.txt y añadir el texto siguiente:

    En este capítulo veremos cómo usar GitHub para alojar repositorios en remoto.

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit con el mensaje "Añadido capítulo 4." Mostrar la historia del repositorio incluyendo todas las ramas.

    cat > capítulos/capitulo4.txt << 'EOF'
En este capítulo veremos cómo usar GitHub para alojar repositorios en remoto.
EOF

git add .
git commit -m "Añadido capítulo 4."
git log --oneline --graph --all

    El parámetro --all hace que git log muestre también los commits de la rama bibliografía.

    17. Trabajar en la rama bibliografía

    Cambiar a la rama bibliografía. Crear el fichero bibliografia.txt y añadir la siguiente referencia:

    Chacon, S. and Straub, B. Pro Git. Apress.

    Añadir los cambios a la zona de intercambio temporal. Hacer un commit con el mensaje "Añadida primera referencia bibliográfica." Mostrar la historia del repositorio incluyendo todas las ramas.

    git switch bibliografía

cat > bibliografia.txt << 'EOF'
Chacon, S. and Straub, B. Pro Git. Apress.
EOF

git add .
git commit -m "Añadida primera referencia bibliográfica."
git log --oneline --graph --all

    18. Fusionar y eliminar la rama

    Fusionar la rama bibliografía con la rama master. Mostrar la historia del repositorio incluyendo todas las ramas. Eliminar la rama bibliografía. Mostrar de nuevo la historia del repositorio incluyendo todas las ramas.

    git switch master
git merge bibliografía
git log --oneline --graph --all

git branch -d bibliografía
git log --oneline --graph --all

    19. Resolver un conflicto de fusión

    Crear la rama bibliografía y cambiar a ella. Cambiar el fichero bibliografia.txt para que contenga las siguientes referencias:

    Scott Chacon and Ben Straub. Pro Git. Apress.
Ryan Hodson. Ry's Git Tutorial. Smashwords (2014)

    Añadir los cambios a la zona de intercambio temporal y hacer un commit con el mensaje "Añadida nueva referencia bibliográfica."

    Cambiar a la rama master. Cambiar el fichero bibliografia.txt para que contenga las siguientes referencias:

    Chacon, S. and Straub, B. Pro Git. Apress.
Loeliger, J. and McCullough, M. Version control with Git. O'Reilly.

    Añadir los cambios a la zona de intercambio temporal y hacer un commit con el mensaje "Añadida nueva referencia bibliográfica."

    Fusionar la rama bibliografia con la rama master. Resolver el conflicto dejando el fichero bibliografia.txt con las referencias:

    Chacon, S. and Straub, B. Pro Git. Apress.
Loeliger, J. and McCullough, M. Version control with Git. O'Reilly.
Hodson, R. Ry's Git Tutorial. Smashwords (2014)

    Añadir los cambios a la zona de intercambio temporal y hacer un commit con el mensaje "Resuelto conflicto de bibliografía." Mostrar la historia del repositorio incluyendo todas las ramas.

    git switch -c bibliografía

cat > bibliografia.txt << 'EOF'
Scott Chacon and Ben Straub. Pro Git. Apress.
Ryan Hodson. Ry's Git Tutorial. Smashwords (2014)
EOF

git add .
git commit -m "Añadida nueva referencia bibliográfica."

git switch master

cat > bibliografia.txt << 'EOF'
Chacon, S. and Straub, B. Pro Git. Apress.
Loeliger, J. and McCullough, M. Version control with Git. O'Reilly.
EOF

git add .
git commit -m "Añadida nueva referencia bibliográfica."

git merge bibliografía

    Al fusionar, Git detecta que ambos commits han modificado las mismas líneas y marca el fichero en estado de conflicto. Se abre el fichero bibliografia.txt, se edita dejando las tres referencias:

    Chacon, S. and Straub, B. Pro Git. Apress.
Loeliger, J. and McCullough, M. Version control with Git. O'Reilly.
Hodson, R. Ry's Git Tutorial. Smashwords (2014)

    Y se completa la fusión:

    git add bibliografia.txt
git commit -m "Resuelto conflicto de bibliografía."
git log --oneline --graph --all

    20. Crear un repositorio en GitHub

    Crear un nuevo repositorio público en GitHub con el nombre libro-git. Añadirlo al repositorio local del libro. Mostrar todos los repositorios remotos configurados.

    Desde la página de GitHub, se pulsa "New repository" y se crea el repositorio público libro-git (sin añadir README, .gitignore ni licencia). Después, en local:

    git remote add origin https://github.com/tu-usuario/libro-git.git
git remote -v

    21. Subir los cambios a GitHub

    Añadir los cambios del repositorio local al repositorio remoto de GitHub. Acceder a GitHub y comprobar que se han subido los cambios mostrando el historial de versiones.

    git push -u origin master

    Al acceder a la página del repositorio en GitHub se puede comprobar que todos los ficheros y el historial de commits se han subido correctamente.

    22. Colaborar en un repositorio remoto

    Colaborar en el repositorio remoto libro-git de otro usuario. Clonar su repositorio libro-git. Añadir el fichero autores.txt que contenga el nombre del usuario y su correo electrónico. Añadir los cambios a la zona de intercambio temporal. Hacer un commit con el mensaje "Añadido autor." Subir los cambios al repositorio remoto.

    git clone https://github.com/otro-usuario/libro-git.git
cd libro-git

echo "Tu Nombre <tu.correo@ejemplo.com>" > autores.txt

git add autores.txt
git commit -m "Añadido autor."
git push

    23. Fork y Pull Request

    Hacer una bifurcación (fork) del repositorio remoto asalber/libro-git en GitHub. Clonar el repositorio creado en la cuenta de GitHub del usuario. Crear una nueva rama autoría y activarla. Añadir el nombre del usuario y su correo al fichero autores.txt. Añadir los cambios a la zona de intercambio temporal. Hacer un commit con el mensaje "Añadido nuevo autor." Subir los cambios de la rama autoría al repositorio remoto en GitHub. Hacer un Pull Request de los cambios en la rama autoría.

    Primero, en GitHub, se pulsa el botón "Fork" en el repositorio asalber/libro-git, lo que crea una copia en nuestra cuenta. Después, en local:

    git clone https://github.com/tu-usuario/libro-git.git
cd libro-git

git switch -c autoría

echo "Tu Nombre <tu.correo@ejemplo.com>" >> autores.txt

git add autores.txt
git commit -m "Añadido nuevo autor."
git push -u origin autoría

    Por último, desde la página del repositorio en GitHub, se pulsa "Compare & pull request" y se crea el Pull Request de la rama autoría para proponer los cambios al repositorio original.

    24. Guardar cambios temporalmente con stash

    Añadir la línea "Capítulo 6: Referencias" al final del fichero indice.txt sin confirmarla. Guardar temporalmente los cambios con git stash y comprobar que el directorio de trabajo queda limpio. Después, recuperar los cambios con git stash pop y comprobar de nuevo el estado del repositorio.

    echo "Capítulo 6: Referencias" >> indice.txt

git status
git stash
git status

git stash pop
git status

    git stash guarda los cambios pendientes y deja el directorio de trabajo limpio, mientras que git stash pop los recupera.

    25. Revertir un commit

    Añadir la línea "Capítulo 7: Conclusiones" al final del fichero indice.txt y hacer un commit con el mensaje "Añadido capítulo 7 al índice." A continuación, revierte ese commit con git revert, de forma que se cree un nuevo commit que deshaga los cambios, sin reescribir el historial. Comprueba el historial.

    echo "Capítulo 7: Conclusiones" >> indice.txt
git add indice.txt
git commit -m "Añadido capítulo 7 al índice."

git log --oneline
git revert --no-edit HEAD
git log --oneline

    A diferencia de git reset, git revert no borra el commit original, sino que crea uno nuevo que deshace sus efectos, por lo que el historial se conserva intacto.

    26. Mostrar los cambios preparados

    Añadir la línea "Capítulo 8: Herramientas" al final del fichero indice.txt. Muestra las diferencias del directorio de trabajo con git diff. A continuación, añade el cambio a la zona de intercambio temporal y muestra las diferencias que están preparadas con git diff --staged.

    echo "Capítulo 8: Herramientas" >> indice.txt

git diff
git add indice.txt
git diff --staged

    git diff muestra los cambios no preparados, mientras que git diff --staged muestra únicamente los que ya están en la zona de intercambio temporal.

    27. Obtener cambios del repositorio remoto

    Desde otro equipo (o directamente desde GitHub), añade un commit al repositorio remoto libro-git. Después, en tu repositorio local, descarga los cambios con git fetch, comprueba el estado y finalmente intégralos con git pull.

    git fetch origin
git status

git pull origin master
git log --oneline

    git fetch descarga los cambios remotos sin fusionarlos, mientras que git pull los descarga y los integra en la rama local.

    28. Crear etiquetas

    Crear una etiqueta v1.0 que marque la versión actual del proyecto. Listar las etiquetas del repositorio y mostrar el historial incluyendo las etiquetas.

    git tag v1.0
git tag
git log --oneline --decorate

    Las etiquetas (tags) sirven para marcar revisiones importantes (por ejemplo, una versión publicada) de forma que se puedan localizar y recuperar fácilmente.

    29. Crear un archivo .gitignore

    Crear un fichero .gitignore que haga que Git ignore los archivos con extensión .log y la carpeta build/. Crear un fichero debug.log y comprobar con git status que Git lo ignora. Hacer un commit del .gitignore.

    cat > .gitignore << 'EOF'
*.log
build/
EOF

touch debug.log

git status
git add .gitignore
git commit -m "Añadido .gitignore"

    Al ejecutar git status, el fichero debug.log no aparece, porque Git lo está ignorando.

    30. Renombrar y eliminar archivos

    Renombrar el fichero capítulos/capitulo1.txt a capítulos/capitulo01.txt y eliminar el fichero capítulos/capitulo2.txt. Comprobar el estado y hacer un commit.

    git mv capítulos/capitulo1.txt capítulos/capitulo01.txt
git rm capítulos/capitulo2.txt

git status
git commit -m "Renombrado capítulo 1 y eliminado capítulo 2"

    git mv y git rm preparan automáticamente los cambios, de modo que no hace falta ejecutar git add.

    31. Filtrar el historial

    Mostrar el historial aplicando distintos filtros: los commits realizados en el último día, los realizados por un autor concreto, los tres últimos commits y un resumen estadístico de los dos últimos.

    git log --oneline --since="1 day ago"
git log --oneline --author="Tu Nombre"
git log --oneline -3
git log --stat -2

    Las opciones --since, --author y -n permiten filtrar el historial, y --stat añade un resumen de los archivos modificados en cada commit.

    32. Navegar a una versión anterior

    Localiza un commit anterior del repositorio y sitúate en él con git checkout. Comprueba que te encuentras en estado detached HEAD y observa cómo los ficheros vuelven a su estado de entonces. Por último, vuelve a la rama master.

    git log --oneline
git checkout <hash-del-commit-anterior>
git log --oneline
git switch master

    Al hacer git checkout sobre un commit (y no sobre una rama), Git entra en estado detached HEAD. Para volver a la rama, se usa git switch master.

    33. Recuperar commits con reflog

    Añade la línea "Capítulo 9: Apéndices" al final de indice.txt y haz un commit con el mensaje "Añadido capítulo 9 al índice." Después, deshaz ese commit con git reset --hard HEAD~1 y comprueba que ya no aparece en el historial. Finalmente, recupéralo usando git reflog.

    echo "Capítulo 9: Apéndices" >> indice.txt
git add indice.txt
git commit -m "Añadido capítulo 9 al índice."

git reset --hard HEAD~1
git log --oneline

git reflog
git reset --hard <hash-del-commit-perdido>
git log --oneline

    git reflog registra todos los movimientos de HEAD, por lo que permite recuperar commits que ya no son accesibles desde ninguna rama.

    34. Abortar una fusión

    Crea una rama conflicto, modifica indice.txt y haz un commit. Vuelve a master, modifica la misma línea y haz otro commit. Fusiona la rama conflicto y, en lugar de resolver el conflicto, aborta la fusión con git merge --abort. Comprueba el estado del repositorio.

    git switch -c conflicto
echo "Línea desde la rama conflicto" >> indice.txt
git add indice.txt
git commit -m "Cambio en la rama conflicto"

git switch master
echo "Línea desde master" >> indice.txt
git add indice.txt
git commit -m "Cambio en master"

git merge conflicto
git merge --abort

git status

    git merge --abort cancela la fusión y devuelve el repositorio al estado anterior a iniciarla, sin aplicar ningún cambio.

    35. Aplicar un commit con cherry-pick

    Crea una rama mejora, añade una línea a indice.txt y haz un commit. Vuelve a master y aplica ese mismo commit sobre master usando git cherry-pick. Comprueba el historial.

    git switch -c mejora
echo "Nueva sección del índice" >> indice.txt
git add indice.txt
git commit -m "Mejora del índice"

git switch master
git cherry-pick <hash-del-commit>
git log --oneline

    git cherry-pick permite aplicar un commit concreto de otra rama sin necesidad de fusionar la rama completa.

    36. Gestionar varios stash

    Realiza dos cambios sin confirmar y guárdalos con git stash (uno tras otro). Lista los stash guardados, recupera el último y elimina el que quede.

    echo "Cambio A" >> indice.txt
git stash

echo "Cambio B" >> indice.txt
git stash

git stash list

git stash pop
git stash drop

    git stash list muestra los cambios guardados, git stash pop recupera el último y lo elimina de la lista, y git stash drop descarta un stash sin recuperarlo.

    37. Crear el README

    Crear un fichero README.md que describa el proyecto libro y hacer un commit con el mensaje "Añadido README".

    cat > README.md << 'EOF'
# Libro de Git

Proyecto de ejemplo para practicar con Git y GitHub.
EOF

git add README.md
git commit -m "Añadido README"

    38. Subir etiquetas al remoto

    Subir las etiquetas del repositorio local al repositorio remoto de GitHub y comprobar que aparecen en la página del repositorio.

    git push origin --tags

    Las etiquetas no se suben con un git push normal; hay que indicarlo expresamente con --tags.

    39. Renombrar una rama

    Crear una rama llamada temporal y, a continuación, renombrarla a nueva-rama con git branch -m. Mostrar las ramas para comprobarlo.

    git switch -c temporal
git branch -m temporal nueva-rama
git branch

    40. Crear y cerrar un issue en GitHub

    En el repositorio libro-git de GitHub, crear un issue titulado "Añadir un capítulo sobre rebase" y, a continuación, cerrarlo una vez anotado.

    Desde la página del repositorio en GitHub:

    1. Pulsar en la pestaña "Issues".
    2. Pulsar el botón "New issue".
    3. Escribir el título "Añadir un capítulo sobre rebase" y una descripción breve.
    4. Pulsar "Submit new issue" para crearlo.
    5. Para cerrarlo, pulsar el botón "Close issue" (o, en la parte inferior, "Close with comment" tras escribir un comentario).
