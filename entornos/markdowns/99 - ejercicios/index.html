    Actividades Prácticas: Entornos de Desarrollo

    Colección de ejercicios prácticos de laboratorio sobre configuración, modularidad, automatización, depuración y empaquetado del entorno de desarrollo. Cada ejercicio incluye el código necesario para que el trabajo se centre exclusivamente en la herramienta y no en programar.

    1. Política de estabilidad en el canal de actualizaciones

    Configura el entorno de desarrollo IntelliJ IDEA para un equipo de producción de aula de modo que se bloquee el acceso a versiones inestables:

    • Accede a File → Settings → Appearance & Behavior → System Settings → Updates.
    • Establece el sistema de actualizaciones en el canal Stable Release.
    • Configura la verificación automática con periodicidad semanal.

    2. Verificación y reporte de parches del sistema

    Fuerza la comprobación manual del estado de actualización del IDE desde el menú superior Help → Check for Updates... antes de una entrega crítica para asegurar que el entorno no tiene parches pendientes de aplicar.

    3. Extensión sintáctica y legibilidad de código

    Instala un módulo externo que mejore el rastreo visual en estructuras de control anidadas en Java:

    1. Localiza en el catálogo de JetBrains (Settings → Plugins → Marketplace) el plugin Rainbow Brackets e instálalo.
    2. Crea una clase con el siguiente código y comprueba que tras reiniciar el IDE se colorean los distintos niveles de llaves y paréntesis:
    public class AnidamientoVisual {
    public static void main(String[] args) {
        for (int i = 0; i < 3; i++) {
            if (i >= 0) {
                while (i < 2) {
                    System.out.println("Nivel 3");
                    break;
                }
            }
        }
    }
}

    4. Desactivación selectiva de extensiones

    Optimiza el consumo de memoria RAM del entorno desactivando temporalmente la extensión GitToolBox desmarcando su casilla en la pestaña Installed de Plugins, sin borrar sus archivos de disco.

    5. Purga y desinstalación completa de módulos

    Elimina definitivamente una extensión instalada previamente en el entorno utilizando la opción Uninstall desde el menú de configuración del complemento, reiniciando el IDE para verificar la limpieza de sus componentes.

    6. Conectividad a bases de datos en IntelliJ Community

    Dota a la versión libre de IntelliJ IDEA de herramientas gráficas para bases de datos relacionales instalando el complemento Database Navigator desde la pestaña Marketplace.

    7. Reasignación de atajos de teclado personalizados

    Optimiza el flujo de trabajo en el editor accediendo a File → Settings → Keymap, localizando la acción Duplicate Line or Selection y asignándole el atajo de teclado Ctrl + D.

    8. Atajo para optimización e importación de paquetes

    Dentro de File → Settings → Keymap, localiza la acción encargada de limpiar importaciones no utilizadas (Optimize Imports) y comprueba el atajo que tiene asignado. Abre una clase con el siguiente código y ejecuta dicha combinación de teclas para comprobar cómo desaparece automáticamente la importación innecesaria de ArrayList:

    import java.util.ArrayList;
import java.util.Scanner;

public class PruebaImports {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("Introduce un texto:");
        String texto = sc.nextLine();
        System.out.println("Texto: " + texto);
    }
}

    9. Estandarización de reglas de formateo de código

    1. En File → Settings → Editor → Code Style → Java, configura sangrías y tabuladores en 4 espacios, y la colocación de llaves al final de la línea (At end of line).
    2. Copia este código desordenado en una clase y aplica el formateo automático (Ctrl + Alt + L) para corregir su indentación:
    public class CodigoDesordenado{
public static void main(String[]args){
int a=1;int b=2;
if(a<b){
System.out.println("Desalineado");
}
}
}

    10. Automatización de sentencias con Live Templates

    Crea una plantilla en vivo en File → Settings → Editor → Live Templates:

    • Abbreviation: scann
    • Context: Java (Statement)
    • Template text: 
      java.util.Scanner teclado = new java.util.Scanner(System.in);

    Prueba su funcionamiento escribiendo scann y pulsando Tab dentro de un método main.

    11. Plantilla en vivo para bucles rápidos

    Crea otra plantilla en vivo con contexto Java: Statement y abreviatura bucle10 cuyo texto de sustitución sea:

    for (int i = 0; i < 10; i++) {
    System.out.println("Iteración: " + i);
}

    Comprueba que al teclear bucle10 y pulsar el tabulador dentro de cualquier método se despliega el bloque completo.

    12. Inyección de argumentos de consola en ejecución

    Crea una clase con el siguiente código:

    public class ArgumentosConsola {
    public static void main(String[] args) {
        System.out.println("Parámetros recibidos: " + args.length);
        for (int i = 0; i < args.length; i++) {
            System.out.println("args[" + i + "]: " + args[i]);
        }
    }
}

    Accede a Run → Edit Configurations... y, en el campo Program arguments, añade los valores alfa beta gamma para comprobar que se leen en consola al pulsar Run.

    13. Configuración de variables de entorno de ejecución

    Crea una clase con el siguiente código:

    public class VariablesEntorno {
    public static void main(String[] args) {
        String entorno = System.getenv("APP_ENV");
        System.out.println("Modo activo: " + entorno);
    }
}

    Accede al perfil de ejecución de la clase en Run → Edit Configurations... y define en el campo Environment variables el par APP_ENV=produccion.

    14. Automatización de tareas previas al arranque (Before Launch)

    Copia la siguiente clase de prueba:

    public class TareaPrevia {
    public static void main(String[] args) {
        System.out.println("Ejecución iniciada tras compilar.");
    }
}

    En Run → Edit Configurations..., localiza el apartado inferior Before launch y comprueba qué acciones se ejecutan antes del arranque (como Build), añadiendo una tarea de construcción de artefactos mediante el botón +.

    15. Depuración con puntos de ruptura condicionales

    Copia el siguiente código en una clase Java:

    public class DepuracionBucle {
    public static void main(String[] args) {
        int acumulador = 0;
        for (int i = 1; i <= 100; i++) {
            acumulador += (i * 2);
            System.out.println("Paso " + i + " -> acumulador: " + acumulador);
        }
    }
}

    Haz clic en el margen izquierdo para fijar un punto de ruptura dentro del bucle, haz clic derecho sobre el punto rojo y marca la casilla Condition escribiendo i == 73. Lanza el programa con el icono de depuración (Debug) y verifica en la pestaña Variables los datos detenidos en ese instante.

    16. Inspección de la pila de llamadas (Call Stack)

    Copia el siguiente código en una clase Java:

    public class PilaLlamadas {
    public static void main(String[] args) {
        int nivel = 1;
        primeraFuncion(nivel);
    }

    private static void primeraFuncion(int n) {
        int resultadoA = n * 10;
        segundaFuncion(resultadoA);
    }

    private static void segundaFuncion(int valor) {
        int resultadoB = valor + 50;
        terceraFuncion(resultadoB);
    }

    private static void terceraFuncion(int dato) {
        int resultadoFinal = dato * 2;
        System.out.println("Proceso concluido: " + resultadoFinal);
    }
}

    Coloca un punto de ruptura dentro de terceraFuncion en la línea de resultadoFinal. Arranca en modo Debug, localiza la pestaña Frames de la ventana inferior para navegar hacia los métodos llamantes (segundaFuncion y primeraFuncion) y comprueba cómo cambian las variables asociadas a cada llamada.

    17. Empaquetado de aplicación ejecutable en Java

    Crea una clase con el siguiente código fuente:

    public class AppEjecutable {
    public static void main(String[] args) {
        System.out.println("Aplicación Java compilada y empaquetada con éxito.");
    }
}

    Configura un artefacto en File → Project Structure → Artifacts (JAR → From modules with dependencies), seleccionando AppEjecutable en el campo Main Class. Construye el fichero desde Build → Build Artifacts y ejecútalo en la terminal del sistema con:

    java -jar out/artifacts/<nombre_carpeta>/<archivo>.jar

    18. Verificación de ejecución independiente de la terminal

    Lleva el archivo .jar generado en la práctica anterior a una carpeta distinta fuera del directorio del proyecto (por ejemplo, a tu carpeta personal home). Abre una terminal en esa nueva ubicación y comprueba que se ejecuta de forma autónoma con java -jar AppEjecutable.jar, demostrando que el artefacto empaquetado no necesita los archivos de configuración del proyecto ni tener abierto IntelliJ IDEA para funcionar.

    19. Inspección del archivo de manifiesto en un paquete JAR

    Localiza el archivo .jar generado en la carpeta out/artifacts/. Haz clic derecho sobre él en el explorador de archivos del sistema operativo y selecciona Abrir con Gestor de archivadores (o ábrelo con un visor ZIP). Entra en la carpeta interna META-INF, abre el archivo MANIFEST.MF con el editor de textos y comprueba que contiene la directiva Main-Class correspondiente a la clase de arranque.

    20. Modificación de la ruta de salida de artefactos compilados

    Accede a File → Project Structure → Artifacts, selecciona el artefacto JAR creado anteriormente y localiza el campo Output directory. Modifica la ruta para que apunte a una carpeta llamada dist dentro de tu proyecto. Reconstruye el paquete con Build → Build Artifacts y comprueba en el árbol de archivos que el ejecutable se ha depositado en la nueva ubicación.
